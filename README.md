## 🔬 Обзор проекта

Данный проект представляет собой низкоуровневую однотабличную СУБД (Storage Engine), разработанную на Python для прямого взаимодействия с дисковой подсистемой (`seek`, `read`, `write`). Ядро хранилища спроектировано в строгом соответствии с принципами построения систем управления базами данных (Database Internals) и исключает полную загрузку таблицы в оперативную память.

Хранилище состоит из двух бинарных структур:
1. **Основной файл данных (`.db`)**: блочная организация с фиксированным размером слота (256 байт) и заголовком со служебными метаданными.
2. **Дисковый индексный файл (`.idx`)**: файловая хэш-таблица с фиксированным количеством корзин (buckets) и разрешением коллизий методом открытой адресации (open addressing with linear probing), гарантирующая алгоритмическую сложность $O(1)$ для точечных запросов (point lookups).

## 📊 Data Science & Data Engineering Фокус

В задачах Data Science и Big Data объемы обрабатываемой информации часто многократно превышают доступный объем оперативной памяти (RAM). Данный проект демонстрирует фундаментальные инженерные решения, применяемые в современных аналитических и транзакционных движках (PostgreSQL, SQLite, ClickHouse, DuckDB).

### 1. Концепция Out-of-Core обработки данных
- **Минимальный Memory Footprint**: Никакие операции (вставка, чтение, поиск, фильтрация, удаление) не требуют загрузки всего датасета в память.
- **Прямой адресный доступ**: Смещение записи в файле вычисляется на основе размера слота ($Offset = HeaderSize + SlotIndex \times SlotSize$), что позволяет дисковой головке/NVMe SSD считывать ровно один 256-байтный блок.
- **Изоляция транзакционных изменений**: Запись изменений происходит побайтово на диск с мгновенной синхронизацией (`flush`), предотвращая порчу данных при сбоях.

### 2. Физическая организация хранения и бинарная сериализация
Данные упаковываются с помощью модуля `struct` в компактный бинарный формат с контролем endianness (Big-Endian `>`):
- **Заголовок файла (32 байта)**:
  - Сигнатура Magic: `STORAGE1` (8 байт).
  - Счётчик активных записей: 4 байта (`>I`).
  - Общее количество выделенных слотов: 4 байта (`>I`).
  - Указатель на начало связного списка удаленных записей (`Free List Head`): 8 байт (`>q`).
  - Резервные байты: 8 байт (`0x00`).
- **Слот записи (256 байт)**:
  - Флаг активности (`status`): 1 байт boolean (`1` — активна, `0` — удалена).
  - Смещение следующего свободного слота (`next_free`): 8 байт (`>q`).
  - Поля атрибутов с фиксированным выравниванием: целочисленный ID (4 байта), строки UTF-8 (80 и 50 байт), вещественное число IEEE 754 (8 байт), количество (4 байта), булевый флаг (1 байт) и паддинг до границы 256 байт.

### 3. Дисковое хэш-индексирование $O(1)$ vs Табличное сканирование $O(N)$
- Для первичного ключа (`id`) развернута файловая хэш-таблица на диске:
  - Хэш-функция: $Hash(id) = (id \times 2654435761) \pmod{BucketCount}$ (мультипликативный хэш Кнута с золотым сечением).
  - Разрешение коллизий: линейное пробирование по слотам индекса.
  - Скорость точечного поиска (`search_by_id`): строго константная $O(1)$ — считывается 16-байтный индексный слот, затем ровно один 256-байтный блок данных.
- Для неключевых атрибутов (`category`, `name`, `price`): реализовано потоковое линейное сканирование (Full Table Scan $O(N)$) через последовательный буферизованный курсор с фильтрацией на лету без утечек памяти.

### 4. Управление свободным пространством (Free List / Tombstone Recycling)
При удалении записи система не выполняет ресурсоемкую дефрагментацию и перемещение байтов на диске:
1. Запись помечается как `Tombstone` (`status = 0`).
2. Смещение слота помещается в голову связного списка свободных слотов (`Free List Head`).
3. При последующей операции `INSERT` движок сначала извлекает свободный слот из Free List за $O(1)$, повторно переиспользуя дисковое пространство и предотвращая неконтролируемое разрастание файлов на диске.

### 5. ETL-пайплайн и интеграция с датасетами (CSV & XLSX)
Проект содержит встроенный модуль пакетного экспорта и импорта данных:
- **Экспорт в CSV / XLSX**: выгрузка дисковых записей в стандартные форматы для последующего разведочного анализа данных (EDA) в Pandas, Polars и Jupyter Notebooks.
- **Пакетная загрузка (Bulk Ingestion)**: возможность наполнения хранилища готовыми внешними датасетами с валидацией схемы типов и автоматической перестройкой дискового индекса.

## 📈 Эмпирический бенчмарк и анализ производительности

Встроенный модуль тестирования (`benchmark.py`) производит замеры латентности ключевых операций на масштабах от 100 до 5 000+ записей:

| Объем датасета ($N$) | Вставка $O(1)$ (мс) | Поиск по ID $O(1)$ (мс) | Поиск по категории $O(N)$ (мс) | Удаление по ID $O(1)$ (мс) |
| :---: | :---: | :---: | :---: | :---: |
| **100** | 0.0126 | 0.0034 | 0.1324 | 0.0143 |
| **500** | 0.0157 | 0.0038 | 0.7404 | 0.0185 |
| **1 000** | 0.0170 | 0.0054 | 1.5551 | 0.0343 |
| **2 500** | 0.0217 | 0.0206 | 4.5794 | 0.0274 |
| **5 000** | 0.0309 | 0.0256 | 8.4852 | 0.0426 |

### Выводы бенчмарка:
1. **Поиск по ключу $O(1)$**: среднее время выборки составляет ~0.005–0.025 миллисекунды независимо от роста объема базы, подтверждая субмиллисекундную константную сложность хэш-индекса.
2. **Линейное сканирование $O(N)$**: время выполнения фильтрации строго линейно возрастает с ростом $N$ (от 0.13 мс для 100 записей до 8.48 мс для 5 000 записей), что наглядно демонстрирует необходимость индексов в аналитике больших данных.

## 📋 Спецификация схемы данных

Предметная область: **Складской учет товаров компании (Warehouse Management)**.

| Поле | Тип Python | Бинарный формат (`struct`) | Размер (байт) | Назначение |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `int` | `>i` | 4 | Первичный ключ (Primary Key, уникальный) |
| `name` | `str` | `80s` | 80 | Наименование позиции (UTF-8) |
| `category` | `str` | `50s` | 50 | Товарная категория |
| `price` | `float` | `>d` | 8 | Розничная цена (IEEE 754 Double Precision) |
| `quantity` | `int` | `>i` | 4 | Количество единиц на складе |
| `in_stock` | `bool` | `>?` | 1 | Флаг наличия на складе |

Каждый слот дополнен служебными байтами `status` (1 байт) и `next_free` (8 байт), и выровнен до фиксированного размера **256 байт**.

## 🚀 Инструкция по установке и запуску

### Требования
- Python 3.10+
- ОС: Linux, macOS, Windows

### Установка зависимостей
Для работы базового движка достаточно стандартной библиотеки Python (`struct`, `os`, `sys`, `time`, `random`, `tkinter`).  
Для импорта и экспорта в Excel (`.xlsx`) требуется библиотека `openpyxl`:
```bash
pip install openpyxl
```

### Запуск графического интерфейса (GUI)
Для интерактивной работы с базой данных (просмотр, добавление, редактирование, удаление, поиск, экспорт/импорт):
```bash
python3 main.py
```
*(Либо `python3 gui.py`)*

### Запуск бенчмарка
Для воспроизведения замеров скорости операций и вывода аналитической таблицы:
```bash
python3 benchmark.py
```

### Использование в Python-коде (API)
```python
from database import Database

db = Database()
db.create("my_dataset.db")

db.insert({
    "id": 101,
    "name": "NVIDIA RTX 4090",
    "category": "GPU",
    "price": 1899.99,
    "quantity": 14,
    "in_stock": True
})

record = db.search_by_id(101)
print("Найдено по хэш-индексу:", record)

results = db.search_by_field("category", "GPU")
print("Результаты фильтрации:", results)

db.delete_by_id(101)
db.close()
```
